# NOVIA HOME — Dashboard Online (secure status integration)

## Deploy dashboard
1. Upload the contents of this folder to the root of the GitHub Pages repository.
2. Keep the Pages origin as `https://ryotjz-commits.github.io`.
3. Reload the dashboard. The service worker cache has been versioned.

## Cloudflare Worker — status endpoint
Dashboard calls:
- `GET https://novia-home-api.ryo-tjz.workers.dev/api/status`

Configure these Worker bindings:
- `BLYNK_AUTH_TOKEN`: **Secret** containing the device auth token.
- `BLYNK_BASE_URL`: **Text**, the exact regional Blynk host, e.g. `https://sgp1.blynk.cloud`.

Do not put the token in HTML, JavaScript, query strings generated by the browser, or GitHub files.

### Important: preserve relay control
The `cloudflare-worker/worker.js` in this package implements `/api/status`.
The dashboard also sends relay commands to `/api/control` using POST. If your currently deployed production Worker already implements `/api/control`, do NOT replace that entire Worker with this file. Merge the `/api/status` handler into the production Worker and retain the existing `/api/control` route, PIN validation, and its secrets.

The status endpoint checks Blynk hardware connectivity using `isHardwareConnected` and reads V0–V3 concurrently. Its response contains `success`, `deviceOnline`, and `channels`; it never returns the auth token.

## Expected status response
```json
{
  "success": true,
  "device": "Novia Home",
  "deviceOnline": true,
  "channels": { "V0": 1, "V1": 0, "V2": 1, "V3": 0 }
}
```

## Verification
1. Check `/api/status` while ESP32 is online and confirm `deviceOnline: true`.
2. Turn ESP32 off and wait for the next dashboard poll; it should show offline.
3. Turn it on again and confirm recovery.
4. Test from mobile data.
5. Confirm `/api/control` still works after merging the status route.
